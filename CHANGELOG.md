# Changelog

The major changes in each Saturn release, for deciding whether to upgrade and what changes when you do. Every release is on [GitHub Releases](https://github.com/Saturn-Technology-Project/Saturn-App/releases) with its downloads, checksums and build provenance; versions below 1.0.0 are previews. Security fixes are also published as [GitHub security advisories](https://github.com/Saturn-Technology-Project/Saturn-App/security/advisories).

## Unreleased

### Security

- **Permission rules now govern Claude Code and Codex turns.** The rules under Settings → Permissions and in a project's `.saturn/settings.json` or `.claude/settings.json` were consulted only by Saturn's own agent loop; a Claude Code turn asked by its own approval setting alone, and a Codex turn asked only in Review mode. A deny now refuses the call and tells the program why, an allow runs it without a card in any mode, and an ask asks even in Bypass, naming the rule on the card. Claude Code's `Bash` is judged as the `code` tool and its file tools as `files`, by action and path; a Saturn skill is judged by its own name. Codex runs its own shell commands and edits without asking Saturn, so a rule cannot reach those.

### Changed

- **A remote run is followed over one SSH connection instead of one a second.** Saturn used to open a new SSH connection every second to ask the worker for new output. It now keeps one connection open while the run goes on, and the worker sends what the run writes as it is written, so samples and logs appear within a fraction of a second and the host sees one connection per run rather than thousands. A stop goes down the same connection. If the connection drops, Saturn says so, catches up a second later from what it already has, and opens it again; the computation on the host is never affected. The worker on the host must be this version of Saturn, as before.
- **LM Studio is now Local server, and MLX is part of it.** The provider under Settings → Models takes any model server on this computer with OpenAI-compatible endpoints: LM Studio, Ollama, vLLM, llama.cpp or `mlx_lm.server`, at the address you give. Saturn lists the models the server has loaded, leaving out embedding and reranking models, and sends no key. The separate MLX provider is gone, since it did nothing LM Studio's path did not; a model saved under it is a Local server model now, at the same address.
- **The semantic code index and its embedding models are gone.** No screen had reached the index since the research interface, and the assistant's tools never used it; the project's files, the research records and memory are what the assistant reads. The bundled embedding model, its download during packaging, the Hugging Face connection it allowed and the Embedding model setting go with it, so the package is about 120 MB smaller and the runtime no longer carries SQLite. An `index/` folder left in `~/.saturn-app` can be deleted.
- **The MCP marketplace is gone,** with its sign-in callback: nothing in the interface had listed or installed from it since the research interface. Servers installed from it earlier stay connected as ordinary MCP servers, and any MCP server is still added by its address or command under Settings → MCP & Skills.

### Fixed

- **A remote job's output comes back as fast as SSH carries it, and a long training log no longer stops it.** Each exchange with the worker carried at most 128 KiB per output and the next waited a second, so a busy log fell minutes behind, and any output past 64 MiB stopped synchronization. Parts are now up to 1 MiB and follow one another while more is waiting, and logs, metrics and resource readings may reach 1 GiB each. Install the worker again on each SSH host after upgrading.
- **The research assistant is made only once.** When two screens asked for the assistant at the same moment on a first start, each could make one, and chats were split between them. They now share the one being made.
- **The Workspace terminal keeps what a command set for the next one.** Each command runs in a new shell, so `source .venv/bin/activate`, `export` or a shell function used to be gone by the next command, and Python ran outside the virtual environment. Each terminal panel now carries its environment, functions and shell variables from one command to the next, so an activated environment stays active and `deactivate` restores the old `PATH`. (An alias carries over only in bash; zsh does not apply aliases inside a script.) A new project's terminal starts fresh. The environment stays inside Saturn's runtime and is never sent to the app. Not on Windows yet.

### Changed

- **Writing a finding in the Workspace is one card.** What you understood takes the full width, with its kind and Save beside each other under it, ⌘↵ (Ctrl+Enter) saves, and an empty list says where findings are kept.
- **The Workspace terminal is denser.** Lines sit at 1.45 times the text size instead of twice it, commands are closer together, and "Clear terminal" sits in the top corner instead of taking a row of its own, so more output fits in the panel.

### Added

- **Home offers to start from two evaluations you already have.** A project without results shows "Compare two evaluations" above the first-study checklist, and the results step offers it too: the assistant previews both files, imports them once you agree, pairs them by sample ID and lists the samples that regressed, so the question and hypothesis can follow once there is something to explain.
- **F12 follows a definition into an installed package.** Going to the definition of `torch.nn.Linear` or a standard-library function opens that file read-only in its own tab, at the definition. Only the selected Python's packages and the Rust toolchain's and crates' sources are read this way; anything else outside the project still is not.
- **The research assistant can have several chats in a project.** + starts a new chat, and the chat's name at the top of the panel opens the project's chats, most recently used first, where one is opened, renamed or deleted. A new chat is named after its first message, and each keeps its own messages and mode. A project opens on the chat it had open last, and a new chat is only kept once a message is sent in it. Your existing chat is kept and named after its first message.

## 0.5.1 (2026-11-08)

### Fixed

- **Workspace files can be created and renamed from the file tree.** New files open immediately, including empty notebooks. Renaming keeps open tabs and unsaved edits, checks an open file's revision, and refuses to overwrite an existing name. F2 renames a focused file.
- **The terminal prompt follows its output.** Commands appear immediately and output accumulates from top to bottom, with the next prompt underneath, rather than in a footer at the panel's bottom. Up/Down recalls commands and restores an unfinished line; Ctrl+L or `clear` clears the scrollback.
- **A training run that lists its checkpoints can register its analysis outputs again.** The checkpoint entries a program writes to its artifacts manifest, for resuming, made "artifacts from run" refuse the whole manifest. They are now passed over, and the figures and JSON beside them are registered.
- **Samples changed after a run was sealed are flagged wherever the run is listed.** The warning on the Experiments page never showed, because the list of runs did not check the seal; only the run's own Evidence did. The list, the Workspace's run tab and the Samples page now say so too.
- **The skills no longer tell a program to write where the sandbox refuses.** The checkpoint, pretraining and task skills said to save into the project folder, which a sandboxed run cannot write; they now say `SATURN_RUN_OUTPUT`, and a project folder only when the person has turned the sandbox off. The starter program writes its files to `SATURN_RUN_OUTPUT` as its own rules say, and the list of run variables is complete.
- **The documents match the runtime on remote runs:** the worker is started without nohup, the host checks every file of the version before running (the old "not certified identical" wording is gone from the docs and from the worker's note), the worker is installed from Environment rather than by hand, a run on the host gets only `SATURN_RESUME_FROM`, and a project's skill can also live in `.agents/skills` or `.claude/skills`.

### Changed

- **The source editor's Tab completes, advances snippet fields or indents**, with Shift+Tab to go back or outdent, local document-word suggestions alongside language completions, and entry-point/test snippets for Python. Python, JS/TS and JSX, Rust, JSON, Markdown, Shell, YAML, TOML, TeX and Lean have syntax support; JSON also reports syntax errors. Existing indentation and CRLF endings are preserved. Recent source tabs keep undo, cursor and scroll while the Workspace is open, and a status bar shows position, indentation, line endings and editing shortcuts. Project-wide type checking and definition navigation still need a language server.
- **The assistant's answers are drawn as Markdown.** Headings, lists, quotes, tables, links, bold and inline code show as such instead of as raw marks; fenced code stays a copyable snippet. A link opens in your browser.
- **A run's evidence shows more of what it records.** Expected: the version's inputs by role, its models with whether each revision pins the weights (a commit or hash) or is a name such as `main` that can move, and what it resumes from. Observed: the platform or host and its working folder, start, end, duration and exit code, the host's commit, where the sandbox let the program write and how many folders it hid, what a resumed run took over, and whether the snapshot was checked after the run. Reported: the settings and the restore the program described, in words rather than raw JSON, and how many report lines it wrote. The sealed samples' hash, size and count are at the bottom.
- **An experiment's seeds can be set in Experiments**, beside the sandbox, as a comma separated list; they are passed as `SATURN_RUN_SEED` and `SATURN_RUN_SEEDS` and frozen into each version. A paused run says since when.

### Added

- **New models appear without waiting for a Saturn update.** Once a provider's API key is saved, Settings lists the models that provider offers that key (Claude, OpenAI, Gemini and DeepSeek), Saturn's names first, and leaves out the ones the key cannot use. Without a key, and for Claude Code and Codex, Saturn's built-in list is shown, and "Other model ID…" takes any model ID by hand. The key is sent only to the provider's own address or one a connected model of it already uses. Prices are still Saturn's own, so a model newer than Saturn is shown unpriced on the Usage page.
- **Claude Mythos 5.1 can be chosen** for the Claude and Claude Code providers, beside Claude Fable 5.1. It is the same model, offered by Anthropic to verified organizations, and is priced the same on the Usage page.
- **Local language servers in the source editor.** Python uses Basedpyright or Pyright with the project's selected interpreter; Environment has a Python language server kit. JS/TS use TypeScript 7's native LSP (project first, then PATH), with the TypeScript 6 language-server wrapper supported; Rust uses rust-analyzer. Connected files have semantic completion, type hover, signatures, versioned push/pull diagnostics and F12 definitions within the project. Unsaved imports survive tab switches and connection restarts. The status bar reports connection state and problems, with restart/setup controls. The runtime owns and reaps server process groups, checks document paths and rejects executable commands and workspace edits. Notebook cells and Windows are not covered yet.
- **Programs to start from, and an SDK.** `research_template` hands the assistant `saturn_run.py`, a dependency-free file an experiment imports to write samples, metrics, its report, checkpoints and artifacts the way Saturn reads them (whole lines, flushed, no duplicate sample, seeds applied and reported, SIGTERM handled), and eight runnable templates to copy into the project and change: a benchmark harness wrapper, a red-team harness, an agent trajectory recorder, a Lean proof checker, a linear-probe trainer, a steering-vector sweep, a resumable training loop, and a paper compile script. A copy is the project's own program, frozen with each version. The SDK is tested against the real Python.
- **The assistant reads less per turn.** The research tools' descriptions are a sixth shorter, with the detail in the `saturn-research-tools` skill; a log gives its last 8 KiB and an output file 32 KiB unless more is asked for; a run's evidence gives the snapshot's file count instead of listing thousands of files unless asked; and `status` cuts a finding's text at 240 characters.
- **The research tools cover what the skills teach.** A `document` artifact keeps a PDF, a model card, a paper or a compile log with its hash, previewed in Experiments (a Markdown card drawn, a PDF shown). `research_read what: "output"` lists and reads what a run's program wrote to `SATURN_RUN_OUTPUT`, such as an agent's trajectories or a proof checker's messages, without running anything. A label can carry a `rater`, and `what: "agreement"` (and the Samples page) gives Cohen's and Fleiss' kappa between raters, against the adjudicated labels and against the scorer. `research_inspect` activations can `save` every layer's raw residual stream as an `.npz` in the project, for probes and steering directions to be trained on in a run. The environment check now reports which programs are on the interpreter's PATH (git, uv, elan, lake, lean, tectonic, latexmk, pdflatex, pandoc), shown in Environment, so a Lean or LaTeX run is promised only when its toolchain is there.
- **Formulas are set in the assistant's answers.** `$…$`, `$$…$$`, `\(…\)` and `\[…\]` in an answer are drawn as mathematics (by KaTeX, with nothing in a formula trusted); a formula KaTeX cannot read is shown as written. Two prices in a sentence are not a formula.
- **TeX and Lean files are highlighted in the Workspace.** `.tex`, `.sty`, `.cls` and `.bib` show commands, environments, comments and formulas apart; `.lean` shows declarations, tactics, nested comments, `#` commands, and `sorry` underlined as what it is. Both readers are Saturn's own.
- **A skill for Lean 4 proofs**, `lean-proofs`: checking proofs as runs, evaluating a model that writes them, and accepting nothing with `sorry`, a new axiom or a statement nobody read. The paper-writing skill says how to compile a LaTeX draft as a run, into the run's output, so the PDF is tied to the sources that made it.
- **Seventeen more bundled skills for the research assistant**, on what a safety lab evaluates and how it finishes work: red teaming, safety benchmarks, behavioral evaluations (sycophancy, deception, sandbagging, reward hacking), agentic evaluations; linear probes, steering vectors, circuit discovery and the tuned lens; reward models and RL, ablation studies, scaling and efficiency (scaling fits, distillation, quantization) and model cards; human evaluation with inter-rater agreement, replication review, data provenance and paper writing.

## 0.5.0 (2026-11-07)

### Fixed

- **The assistant's browser can be watched again, in the Workspace.** Since the research interface, an agent browsing in Saturn's own browser (the default) did so out of sight: the Browser tab its settings spoke of was gone. The Workspace now opens a Browser tab beside your files when the assistant opens a page, showing the page live with the cursor the assistant points, clicks and types with, now a black pointer with Saturn beside it so it is plain whose it is; the page fits or shows at its actual size. While you are elsewhere, the assistant panel says it is browsing and leads there.

### Changed

- **Running an experiment says what it does.** The Workspace's bare command box and Run button are now an experiment bar beside the results' tabs, leaving the editor its room: it names the experiment (or starts a new one), takes the command after a `$`, and **Freeze and run** says that it keeps the code as a version before running it. While the run goes, the bar shows its status and version, with Pause and Stop beside them. **Open in Experiments** and, on the Experiments page, **Edit in Workspace** move between the two on the same experiment, and Experiments can now run its newest version as it was frozen.
- **The workspace's samples and questions are easier to read.** Each sample id now fits on one line, and a long one keeps its end in view (the full id shows on hover). A sample's scores form a small table instead of raw JSON, with zeros dimmed so what the scorer found stands out. The sidebar's questions sit apart, each behind a thin rule and up to three lines, with how many there are and a link to all of them. The sample list and the sample beside it scroll on their own, and the arrow keys move through the list.
- **A worker of another Saturn version is refused.** Every request now carries Saturn's version, and a check compares it, so a host can no longer run jobs with a worker that does not match the app. After upgrading, use **Install worker** in Environment once for each SSH host whose worker came with an earlier version.
- **Samples name the model a line is about.** A line that names no model used to show "Unnamed model". It now shows the version's model when the version has only one, the model's id when that id is not recorded under Models, and otherwise "Model not recorded", with a note on how to fix it. The runs table names models the same way.
- **"Scorer: no word" is gone from every sample line.** The scorer's word is shown only when the program wrote one; the scores are beside it either way.

### Added

- **Tabs in the Workspace.** Every file you open gets a tab above the editor; switching keeps a tab's unsaved text, marked with a dot, and closing one with changes asks first. The tabs reopen with the project.
- **Local models through MLX.** On a Mac with Apple silicon, choose MLX in Settings → Models to use a model served by `mlx_lm.server` (`pip install mlx-lm`), with no LM Studio in between. Saturn lists the models the server can load; like an LM Studio model, it needs no key and costs nothing, and it must support tool calling to act as the research assistant.
- **Saturn installs its own worker on an SSH host.** In Environment, Connect finds this version's worker on the host and uses it; when it is missing or another version, Install worker puts the right one in `~/.saturn/worker/<version>` in your home folder, with no administrator rights. It is this computer's own program when the host is the same kind of system, and otherwise the release's Linux worker (x86-64 or ARM), used only if it matches the hash built into this Saturn, and hashed again on the host. Releases now carry these workers. The assistant can see whether the worker is ready; installing stays yours.
- **A run can be paused and continued.** A running experiment can be held where it is and let go on later, from its row in Experiments or by the assistant. It keeps its memory, and the GPU's, while paused, and the run says how long it spent paused. A paused run can still be stopped.
- **A run that stopped, was interrupted or failed can be resumed.** Resuming starts a new run of the same version that takes over where the old one was: an evaluation keeps the samples it finished, and its program skips them; a training run's program restores the last checkpoint the run listed, and its curve goes on from that step. The new run, and its evidence, say which run it resumed and what came along. The assistant can pause, continue and resume runs too, and a new skill tells it how, and how to write a program that can be resumed.
- **An experiment can be renamed.** The experiment page now shows the experiment's name above its question and hypothesis, and changing it there renames it; its versions and runs stay with it. A blank name is not saved, and a change made meanwhile elsewhere, by the assistant for one, is reported rather than overwritten.
- **Training metrics follow a run while it goes.** The experiment page showed a training run's curve only once the run had finished. It now shows the run still going, adds each metric as the program writes it, and reads the last ones when the run ends; before the first metric it says it is waiting. A long run's curve stays quick to draw.

## 0.4.0 (2026-11-06)

### Security

- **A project's files can no longer start a remote job.** Saturn reconnects only remote runs it started from this computer, recorded in its own data folder. Before, a project folder could carry a "running" remote run, and Saturn would connect to that host and run the command from the project's files when it next started. A remote job whose folder is gone is reported as interrupted instead of being started again, and an output too large to bring back ends the run with that reason instead of retrying forever.
- **An agent's GitHub tools could read any git repository on this computer.** A repository owner or name such as `../..` was used as a folder path, so a prompt-injected agent could read a repository outside its project. Owners and names must now be plain names. A remote on a host that merely ends in `github.com` also no longer counts as GitHub.
- **The code index could send a linked or hidden file to the embedding model.** When the index was asked to refresh named files, a link to a file outside the project, a hidden file such as `.env`, or a file in a folder next to the project with a similar name was indexed. With an OpenAI-compatible embedding connection, that text left the computer. Named files now follow the same rules as a whole pass.
- **The agent browser's screenshot tool could write outside the workspace.** A file path such as `../../secrets.json` or an absolute path was accepted, and the tool counts as a read, so it did not ask first. A screenshot now stays in the workspace, also through links, and a recording's name stays one folder under `recordings`.
- **Computer use only starts apps.** Finding an app by path or name handed it to the system's opener, so a script, a document or a web address given as an "app" would run outside the sandbox.
- **An agent's customization tools stay in the project.** A rule named `../../somewhere` was written outside it, and a link in a cloned repository could lead a new rule, skill or plugin out of it, or bring a file from elsewhere into a migrated workflow or a bundled plugin.
- **The web tool, the agent browser and the Browser tab could reach this computer and the private network through an IPv6 spelling of a private address** (such as `[::ffff:127.0.0.1]`). These addresses are now refused, along with carrier-grade NAT (which Tailscale uses), multicast and other reserved ranges. The web tool and the Browser tab now check an address at the moment of connecting, so a name cannot pass the check and then resolve somewhere private, and `browser_navigate` refuses names that resolve to private addresses.
- **Opening a terminal on Windows no longer puts the folder's path on a command line**, where a folder name containing `&` could run a command.
- **The file view no longer follows a symbolic link out of the workspace**, which a cloned repository could use to show a file from elsewhere on the computer.
- **An agent's `files` tool no longer follows a symbolic link out of the workspace.** A cloned repository could bring a link that let the agent read or change files elsewhere on the computer, and writing through a link also got around the command sandbox. Links that stay inside the workspace still work.
- **Reverting an agent's changes no longer writes through a symbolic link.** A command the agent ran could put a link in place of a file it had changed, so that reverting wrote the original contents to wherever the link led. The revert now stops and says so.
- **Attaching a file or folder with `@` no longer follows a symbolic link out of the project**, which a cloned repository could use to put a file from elsewhere on the computer into a message.
- **A project's rule files, skills and commands, and a plugin's files, can no longer be links to files elsewhere on the computer.** A cloned repository could make `AGENTS.md` a link to, say, a credentials file, and its contents went into every prompt sent to the model's provider. Such links are now ignored; links that stay inside the project still work.

### Fixed

- **On Windows, the assistant's file tools name paths with forward slashes,** as on macOS and Linux, rather than backslashes.
- **A run's sample and token counts follow a samples file rewritten moments after the last read.** A rewrite of the same size could leave the file's size and time as they were, most of all on Windows, whose file times move in steps, and the counts stayed on the old content. A file changed in the last two seconds is now read to check.
- **Quitting Saturn can no longer leave the runtime running.** If one of the steps of stopping hung, such as ending an experiment run, the runtime stayed on in the background. It now exits within ten seconds of being asked, whatever is left.
- **The browser tools no longer report Chrome closed on a slow first start.** Chrome had ten seconds to start, and its first start, which makes its profile, could take longer on a busy computer. It now has thirty, a start that fails is tried once more, and when Chrome still does not start the tool says whether it ended or did not answer, and what it printed.
- **Computer use reads a WebKit window fully on the first look.** WebKit builds a page's accessibility tree only once something asks for it, so a fast first read of a window holding one (Saturn itself, Safari) could find nothing inside. On macOS the tree is now read again, briefly, when it looks like a page still being built.
- **The Browser panel's live view no longer stays on an older picture.** A frame that came less than 80 ms after the one before was dropped, and a page that had gone still sent no more, so the panel could keep showing the page as it was before the last scroll or click. The newest frame now waits its turn instead.
- **A committed link that leads out of the project no longer passes as verified.** A run read whatever the link pointed to, while its evidence said every input was verified. Such a link is now listed as uncontrolled, with its target and the target's hash at the start, and a target that changes during the run is recorded as changed.
- **A run whose inputs changed while it ran is no longer compared as if it measured its version.** Paired comparisons, the score chart and the same sample across runs now say it is not comparable, and name the inputs that changed.
- **A research bundle keeps each run's evidence.** Exports now carry `evidence.json`, the program's `report.jsonl` and a remote run's `snapshot.json`, so an imported run still shows what was expected, observed and reported.
- **A run's evidence lists the models the program reported as source and revision**, one per line, instead of raw JSON running off the edge.
- **On Linux, runs are monitored and ended properly.** Saturn thought every process group had already ended, so resource readings stopped at once, and stopping a run or an environment job could leave its child processes running.
- **`main`, `latest` and short commits no longer count as pinned weights.** Only a full commit or hash pins a model; anything else is shown as floating, since the name can come to mean other weights. Freezing an experiment whose model is named this way makes a new version once.
- **Imported results are marked, and are never compared as if verified.** An imported run and its experiment say so in Experiments and in the score chart, and two imports that describe the same evaluation no longer get a 95% interval, since nothing checks their data or scorer.
- **Project analysis outputs stay reachable.** An analysis panel can browse all project outputs while a run or session is selected, including snapshots that have no run link.
- **Behavior slices read imported metadata.** A default category can come from `metadata.category`; nested fields such as `metadata.group.language` can be selected explicitly, while a top-level category keeps precedence.
- **Screens open fast on large runs.** A finished run's samples are read once and remembered, instead of again every time Lineage, Experiments, Samples or Home opened, which took seconds on a large run.
- **The sidebar reads at a glance.** Each screen's icon and name share a line, only the screen you are on is highlighted, and Settings has a gear. In a narrow window the sidebar shrinks to its icons.
- **A step waiting for your approval can always be seen.** Once a turn had said anything, its steps folded away with the approval card inside them, so a task could sit waiting with nothing to answer in view. The card now comes last in its turn.
- **Settings look the same throughout.** Every field and menu shares one style, the model form is laid out properly, each built-in tool says what it is for, and About describes the research workbench. Permissions and Hooks say what they are for in a line, with the details folded away, and Telemetry's traces and logs show 25 at a time.
- **Lineage reads as one tree.** Each model takes one line under the one it came from, with its score in a column, instead of a card and a section per branch.
- **The Samples list is easier to scan.** Each sample takes one line, a long name keeps its start and end, a dot shows whether it has been reviewed or has errors, and the run and filter stay in view as you scroll.
- **A chat follows what it says.** The assistant and a task's log now stay at the newest text as it arrives. Scrolling up to read leaves you there, and scrolling back down picks it up again. A task's log did not scroll at all before.
- **A second approval no longer goes missing on Codex.** When Codex repeated a call right after you approved the first one, the new card could vanish and leave the run waiting with nothing to answer.
- **An assistant on Claude Code now hears new instructions in a chat it already has.** Claude Code kept the instructions from a chat's first message, so an existing chat never learned about Saturn, and edits to memory or project rules did not reach it either. It now gets the current ones on every message, and the conversation stays as it was.
- **An assistant on Codex now hears new instructions in a chat it already has.** Codex was told an agent's instructions only when a thread opened, so an existing chat never learned about Saturn, and answered that it had no guide to the interface. A resumed thread now hears them when they change, and an existing one hears them once.
- **The window stays put.** The whole interface could be dragged up and down; now only the panes inside it scroll.
- **The tour keeps its place.** Connecting a model or choosing a folder in its last step sent it back to the start, and its card could stay hidden in a window behind others.
- **A model or MCP server in use can be removed again.** Removing one said "Connection is still used by an agent", with no screen left to change that agent on. Saturn now says who uses it and, once you agree, moves them to another model (or leaves them with none) or takes the server off their lists. The research assistant picks up a model again when one is connected.
- **A model's mechanism no longer shows a result from a corrected helper.** Sweeps made before a helper changed stay with the run and are counted apart, so an old number cannot stand for the model.
- **"Restored" follows the scorer.** A program that writes `alternative` on its sample lines gets a layer sweep counted by the logit margin a two-way scorer judges, with the top token shown beside it; without one the sweep says it counts the top token.
- **The Samples list keeps your place.** Labeling a sample, or any other change to the records, no longer sends the list back to its first page, and the list loads the whole run by itself up to 20,000 lines.
- **A run is only warned about against whole runs.** A failed or stopped run no longer gets a sample-count warning, or causes one for the next run.
- **Environment jobs have a deadline**, 30 minutes by default and adjustable before creating, installing or syncing. A timeout stops the whole process group, keeps the output and allows a retry; Stop also clears children that ignore the first signal.
- **Run counters recover when a script rewrites its samples.** Lines and reported tokens are recounted from the current file, Resources flags the rewrite, and throughput no longer crosses the reset.
- **Disputed samples are found across the whole run**, including past 5,000 lines. Experiments can map custom label names to scorer words; agreement and review warnings use the same rule, and switching runs or filters cannot show a late response from the preceding choice.
- **Sample label buttons stay on one row in narrow panes.** Scroll the comparison horizontally, including from the keyboard, while the assistant is open.
- **The tour's highlight follows the current step**, including panels that appear later, without flashing or sliding from the previous target.
- **A model's mechanism shows every tied best layer**, and says when no layer restores a sample.
- **Looking inside uses the right side of the final normalization.** A last-block patch used an already normalized residual, and the final layer's reading normalized it again. Both could change the result. New readings and sweeps use a cache key that includes the helper's hash, so corrected results are computed again while earlier results stay intact.
- **The app keeps its runtime running.** It restarts a runtime that dies, shows where the runtime stands until it answers instead of a blank error, and no longer uses another Saturn that happens to be on its port, which could overwrite the same data folder. Settings and the command palette offer a restart.

## 0.3.1 (2026-10-22)

### Security

- **A project's settings files can no longer pre-approve tool calls.** The allow rules in a project's `.saturn/settings.json` and `.claude/settings.json`, which come with the folder (a cloned repository, say), applied without being shown to you, and a rule allowing every shell command was not refused. A repository could therefore let an agent run commands without an approval card. Now their deny and ask rules apply at once, their allow rules only after you allow that exact set in **Settings → Permissions** (any change asks again), and a rule that allows every command is never applied. Affects v0.3.0 and earlier: upgrade, and check the project rules of any repository you opened.

### Fixed

- **Saturn no longer quits seconds after launch while indexing a project.** The built-in embedding model asked for one 2 GiB block of memory on large files, which Electron answers by ending the process. It now works in smaller batches and uses a fraction of the memory.
- An approval card for a Claude Code or Codex agent could refuse an answer given the moment it appeared ("This approval is no longer waiting"). The card is now shown only once Saturn is listening for the answer.

### Changed

- The TypeScript SDK (`@saturn-app/sdk`) moved to its own repository, [Saturn-SDK](https://github.com/Saturn-Technology-Project/Saturn-SDK), laid out for more languages.

### Added

- `SECURITY.md` (how to report a vulnerability, privately by email or through GitHub) and a [threat model](docs/threat-model.md) with the scope for an external security review.
- OpenSSF Scorecard, CodeQL code scanning and secret scanning on the repository.
